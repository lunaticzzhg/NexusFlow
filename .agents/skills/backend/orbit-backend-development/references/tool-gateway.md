# 工具网关与外部副作用

本专题仅在 feature 接入第三方读取或写入能力时适用。当前工程没有连接器、工具网关或外部动作运行时；不得为未来能力预置空接口、凭据表或伪成功路径。

## 能力边界

读取与写入能力分开建模。创建日历、提醒、通知、工单、支付、删除或任意已连接账户变更均是写操作，必须由服务端在已持久化的授权/审批边界后执行并可审计。工具不得接收任意模型文本、原始用户 token，也没有直接修改业务终态的权限。

## 规则

- 网关校验连接器专属 schema、账户/tenant 绑定、允许目的地、风险等级和动作新鲜度；执行前再次校验授权。
- 使用服务端生成的稳定动作幂等键；在推进业务状态前持久化外部引用、尝试、结果和脱敏错误。
- 连接器凭据按 tenant 隔离并遵循最小权限；轮换/撤销授权并掩码 secret。连接器输入/输出均不可信，限制大小并隔离 prompt injection 内容。
- 未知外部结果必须进入可对账状态，不能盲目重试；重复写入前按幂等键或外部引用查询连接器。

## 验收

证明未批准、过期或编辑后失效的动作被阻止；重复事件只有一次外部写入；发送后超时可对账；tenant A 永不使用 tenant B 凭据；审计记录对每种结果均脱敏。

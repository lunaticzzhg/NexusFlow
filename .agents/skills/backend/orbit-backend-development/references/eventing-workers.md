# 事件、Worker 与恢复

本专题仅在当前 feature 已明确需要异步推进、可靠重试或外部副作用时适用。当前后端没有 Worker、broker producer/consumer、Outbox 发布器或租约领取器；不得把本文件的示例当作已存在的运行时。

## 设计规则

- Worker 是持久化状态机的执行器，不是 HTTP 请求的延续。HTTP 命令先完成短事务；异步工作从已持久化的事件或待处理记录恢复。
- 消费至少一次消息时，按稳定 event ID 或自然副作用键去重；分区顺序不能替代去重。
- 用版本与 `lease_until` 领取可恢复工作。只回收已过期租约；副作用前重新检查取消、终态与授权条件。
- 失败分为可解释终态与有限预算的可重试失败。退避耗尽写入可观测终态或 DLQ；不得无限重试或依赖内存完成标记。
- 事件、日志和外部调用携带 correlation/causation ID；每个可恢复阶段后持久化 checkpoint 或等价状态。
- 本地业务状态与 Outbox 变更持久化前不得确认 broker 成功；数据库提交也不得依赖 broker 可用。

## 启用与验证

引入时在同一 feature 增加持久化状态、Outbox/投递适配器、消费者运行入口、关闭生命周期和验收测试。至少覆盖重复投递、租约过期恢复、可重试失败/退避耗尽、取消竞态及 broker 不可用。只有独立吞吐、故障域、数据所有权和运行契约真实存在时，才拆为独立部署单元。
